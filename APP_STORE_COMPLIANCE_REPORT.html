1. Architecture Decisions

APS App Type: Traditional Web App

  • 3-legged OAuth (Authorization Code)
  • Confirmed against Autodesk's own BIM 360 publisher documentation — no server-to-server mandate exists for this category of app
  • Validated against a live, approved comparable listing (Enlaye for Autodesk Forma), which uses the identical flow

One Publisher-Owned APS App (Model B)

  • A single Client ID/Secret, owned by Digibuild, used for every customer
  • Customers never create their own APS app or see a Client ID/Secret
  • Replaces the previous per-tenant "bring your own credentials" flow

Existing Login System Retained

  • digibuild.ch (Firebase) accounts stay as the primary login
  • No change to how licenses are tied to an account
  • A larger move to Autodesk-only sign-in was considered and parked — not required for this submission

Listed as Free

  • The store listing is a credibility signal, not the sales channel
  • Real subscriptions continue through the existing PayPal flow on Digibuild's own site
  • Avoids routing revenue through Autodesk's store checkout and commission terms

3. Key Verified Findings

Several items were resolved by direct verification against Autodesk's own current documentation or the app's actual code, rather than by writing new code — worth recording since they overturn earlier assumptions:

Region routing was already solved by Autodesk, not by this app
Autodesk's own documentation (dated March 2024) confirms automatic region routing for every API this app calls; only the Model Derivative API and pre-2021 Viewer versions ever needed manual handling, and this app uses neither.
Licensing was already automatic
Tracing the actual purchase-to-activation code path showed license keys are shown on-screen immediately and pre-filled into the registration link — not the "email me a key" pattern Autodesk rejects. Confirmed with a real test purchase.
A real access-control gap was found and closed
One admin action wrote directly to the database from the browser, relying on database rules configured outside this codebase rather than the server's own authentication middleware. Fixed by routing it through a new authenticated endpoint, matching every other admin action in the app.
Scope over-requesting was minimal, not extensive
A full audit of every Autodesk API call in the codebase found exactly one unused scope, not the several originally assumed — the rest are all genuinely exercised by real functionality (folder permissions, user/company management).
